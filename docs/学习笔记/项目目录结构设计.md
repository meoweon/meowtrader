# MeowTrader 项目目录结构设计

## 当前结构分析

### 存在的问题

1. **`scripts/` 目录职责不清**
   - 混合了 PyInstaller 打包脚本和通用工具脚本
   - `hooks/` 是 PyInstaller 专用的，应该与打包脚本放在一起

2. **`app/` 目录使用情况**
   - ✅ **正在使用**：`build.py` 中引用了 `app/desktop/main.py` 作为打包入口
   - 包含 3 个入口：`desktop/`, `server/`, `web/`
   - **不应删除**，这是应用的入口层

3. **`packaging/` 目录未充分利用**
   - 存在 `packaging/pyinstaller/` 目录，但没有被使用
   - PyInstaller 相关文件应该移到此处

## 迁移步骤

### 步骤 1：创建新的目录结构

```powershell
# 创建 packaging/pyinstaller 目录结构
New-Item -ItemType Directory -Path "packaging/pyinstaller/hooks" -Force

# 移动 PyInstaller 相关文件
Move-Item -Path "scripts/build.py" -Destination "packaging/pyinstaller/build.py"
Move-Item -Path "scripts/hooks/*" -Destination "packaging/pyinstaller/hooks/"

# 删除空的 hooks 目录
Remove-Item -Path "scripts/hooks" -Force
```

### 步骤 2：更新引用

需要更新的文件：

1. **`packaging/pyinstaller/build.py`**
   - 更新 `PROJECT_ROOT` 路径计算（因为目录层级变了）
   - 更新 `hooks_dir` 路径

2. **`start.bat`**
   - 如果引用了 `scripts/build.py`，需要更新

3. **文档**
   - `README.md` 中的示例命令
   - `docs/学习笔记/` 中的相关文档

### 步骤 3：更新 build.py 中的路径

```python
# 旧的路径计算（在 scripts/build.py 中）
PROJECT_ROOT = Path(__file__).parent.parent

# 新的路径计算（在 packaging/pyinstaller/build.py 中）
PROJECT_ROOT = Path(__file__).parent.parent.parent

# hooks 目录路径更新
hooks_dir = PROJECT_ROOT / "packaging" / "pyinstaller" / "hooks"
```

## 目录职责说明

### `packaging/` - 打包工具目录

**目的**：集中管理所有打包相关的工具和脚本

**子目录**：
- `pyinstaller/`：PyInstaller 打包脚本和 hooks
- `docker/`：Docker 镜像构建
- `nuitka/`：Nuitka 打包（可选）

**原则**：
- 打包工具和脚本应该与源代码分离
- 不同打包工具各自独立目录
- 便于维护和扩展

### `scripts/` - 通用工具脚本

**目的**：开发和运维相关的通用工具脚本

**包含**：
- 环境设置脚本（`setup_env.py`）
- 依赖管理脚本（`install.py`）
- 测试脚本（`test_imports.py`）
- 工具脚本（`copy_dlls.py`）

**不包含**：
- 打包相关的脚本（应放在 `packaging/`）
- 应用入口（应放在 `app/`）

### `app/` - 应用入口层

**目的**：定义应用的启动入口

**包含**：
- `desktop/`：桌面客户端入口
- `server/`：服务端入口
- `web/`：Web 服务入口
- `ui/`：UI 组件

**职责**：
- 提供应用的启动入口点
- 负责初始化运行时环境
- 加载配置并启动引擎

## 优化后的优势

### 1. 职责清晰

- **打包工具**：集中在 `packaging/` 目录
- **通用脚本**：集中在 `scripts/` 目录
- **应用入口**：集中在 `app/` 目录

### 2. 易于维护

- 打包脚本和 hooks 放在一起，便于管理
- 新增打包工具时，只需在 `packaging/` 下新建子目录
- 通用脚本独立，不受打包工具影响

### 3. 符合最佳实践

- 打包工具与源代码分离
- 目录命名清晰，易于理解
- 便于 CI/CD 集成

## 注意事项

### 1. `app/` 目录不应删除

- ✅ **正在使用**：`build.py` 引用 `app/desktop/main.py` 作为打包入口
- ✅ **有实际功能**：包含桌面、服务器、Web 三种启动模式
- ✅ **符合架构设计**：这是应用的入口层

### 2. 迁移后的使用方式

```bash
# 旧的打包命令
.venv/Scripts/python.exe scripts/build.py

# 新的打包命令
.venv/Scripts/python.exe packaging/pyinstaller/build.py
```

### 3. 可以创建快捷方式

在 `scripts/` 中创建包装脚本：

```python
# scripts/build.py（新的，作为快捷方式）
"""打包脚本快捷方式"""
import subprocess
import sys
from pathlib import Path

PROJECT_ROOT = Path(__file__).parent.parent
build_script = PROJECT_ROOT / "packaging" / "pyinstaller" / "build.py"

if __name__ == "__main__":
    subprocess.run([sys.executable, str(build_script)] + sys.argv[1:])
```

这样旧命令仍然可以工作。

## 总结

| 目录 | 当前状态 | 建议操作 | 说明 |
|------|---------|---------|------|
| `app/` | ✅ 在使用 | **保持不变** | 应用入口层，不应删除 |
| `scripts/build.py` | PyInstaller 脚本 | **移动到** `packaging/pyinstaller/` | 打包工具应该独立 |
| `scripts/hooks/` | PyInstaller hooks | **移动到** `packaging/pyinstaller/hooks/` | 与打包脚本放在一起 |
| `scripts/` 其他文件 | 通用脚本 | **保持不变** | 通用工具脚本 |
| `packaging/pyinstaller/` | 存在但未使用 | **放入打包脚本** | 充分利用现有结构 |
