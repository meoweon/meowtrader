# PyInstaller 打包目录结构说明

本文档说明 MeowTrader 打包后的 `dist/MeowTrader/_internal` 目录结构。

---

## 基础知识

### 一、文件后缀名说明

#### 1. Python 相关文件

| 后缀名 | 说明 | 示例 |
|--------|------|------|
| `.py` | Python 源代码文件 | `main.py`, `__init__.py` |
| `.pyc` | Python 字节码文件（已编译） | `__pycache__/module.cpython-313.pyc` |
| `.pyo` | Python 优化字节码文件（已弃用） | - |
| `.pyd` | Python 扩展模块（Windows） | `_ta_lib.cp313-win_amd64.pyd`, `_ssl.pyd` |
| `.so` | Python 扩展模块（Linux/macOS） | `_ta_lib.cpython-313-x86_64-linux-gnu.so` |
| `.pyx` | Cython 源代码文件 | `pricing.pyx` |
| `.pxi` | Cython 包含文件 | `_abstract.pxi` |
| `.pyi` | Python 类型存根文件 | `_ta_lib.pyi`, `functools.pyi` |
| `.py.typed` | 类型检查标记文件 | `py.typed` |

**详细说明**：

- **`.pyd`**（Python Dynamic）：
  - Windows 上的 Python 扩展模块，本质是 DLL 文件
  - 包含用 C/C++/Cython 编写的代码，提供高性能功能
  - 通常包含数值计算、加密、网络等底层功能
  - 示例：`_ssl.pyd`（SSL/TLS 支持）、`_ta_lib.pyd`（TA-Lib 核心）

- **`.pyc`**（Python Compiled）：
  - Python 字节码文件，`.py` 文件编译后的结果
  - 加快模块导入速度（避免重复编译）
  - 存储在 `__pycache__/` 目录中
  - 命名格式：`module.cpython-{version}.pyc`

- **`.pyi`**（Python Interface）：
  - Python 类型存根文件，用于静态类型检查
  - 包含函数签名和类型注解，但不包含实现
  - 工具如 `mypy`、IDE 使用它们进行类型检查

#### 2. 动态链接库文件

| 后缀名 | 说明 | 示例 |
|--------|------|------|
| `.dll` | Windows 动态链接库 | `python313.dll`, `libcrypto-3.dll` |
| `.so` | Linux 共享对象库 | `libcrypto.so.3`, `libssl.so.3` |
| `.dylib` | macOS 动态库 | `libcrypto.3.dylib` |
| `.lib` | Windows 静态/导入库 | - |
| `.a` | Linux/macOS 静态库 | - |

**详细说明**：

- **`.dll`**（Dynamic Link Library）：
  - Windows 上的动态链接库
  - 包含可被多个程序共享的代码和数据
  - 运行时动态加载，减小可执行文件体积
  - 类型：
    - **Python 运行时 DLL**：`python313.dll`（Python 解释器核心）
    - **系统 API DLL**：`api-ms-win-core-*.dll`（Windows API 转发）
    - **C/C++ 运行时 DLL**：`vcruntime140.dll`（Visual C++ 运行时）
    - **第三方库 DLL**：`libcrypto-3.dll`（OpenSSL 加密库）

- **Python 扩展 `.pyd` 的本质**：
  - `.pyd` 文件实际上就是 `.dll` 文件，只是命名不同
  - 可以重命名为 `.dll`，但 Python 无法直接加载
  - 包含特殊的 Python C API 入口点，可以被 `import` 语句导入

#### 3. 压缩和归档文件

| 后缀名 | 说明 | 示例 |
|--------|------|------|
| `.zip` | ZIP 压缩文件 | `base_library.zip` |
| `.whl` | Python Wheel 包 | `numpy-2.4.1-cp313-win_amd64.whl` |
| `.tar.gz` | tar + gzip 压缩 | `source.tar.gz` |
| `.egg` | Python Egg 包（已弃用） | - |

**详细说明**：

- **`base_library.zip`**：
  - PyInstaller 创建的 Python 标准库压缩包
  - 包含所有纯 Python 标准库模块（如 `os`, `sys`, `json` 等）
  - 运行时自动解压到内存，不写入磁盘
  - 减小打包体积，加快启动速度

#### 4. 数据文件

| 后缀名 | 说明 | 示例 |
|--------|------|------|
| `.json` | JSON 配置文件 | `edition.all.json`, `settings.json` |
| `.toml` | TOML 配置文件 | `pyproject.toml` |
| `.yaml` / `.yml` | YAML 配置文件 | `config.yaml` |
| `.ini` | INI 配置文件 | `config.ini` |
| `.xml` | XML 文件 | `manifest.xml` |
| `.txt` | 文本文件 | `README.txt`, `requirements.txt` |
| `.ico` | Windows 图标文件 | `vnpy.ico`, `app.ico` |
| `.png` / `.jpg` | 图像文件 | `logo.png` |

#### 5. 可执行文件

| 后缀名 | 说明 | 示例 |
|--------|------|------|
| `.exe` | Windows 可执行文件 | `MeowTrader.exe` |
| 无后缀（Linux/macOS） | Unix 可执行文件 | `meowtrader` |

#### 6. 包元数据目录

| 后缀名 | 说明 | 示例 |
|--------|------|------|
| `.dist-info/` | Python 包元数据目录 | `numpy-2.4.1.dist-info/` |
| `.egg-info/` | Python Egg 元数据（已弃用） | - |

**详细说明**：

- **`.dist-info/`**：
  - Python 包的标准元数据目录（PEP 376）
  - 包含包的版本、依赖、许可等信息
  - 通常位于 `site-packages/` 中
  - 内容：
    - `METADATA`：包的基本信息
    - `RECORD`：文件清单
    - `INSTALLER`：安装工具
    - `WHEEL`：Wheel 格式信息（如果是从 wheel 安装）

### 二、Python 模块类型

#### 1. 纯 Python 模块（.py）

- 用 Python 编写的模块
- 可直接读取源代码
- 示例：`vnpy/trader/engine.py`

#### 2. 扩展模块（.pyd / .so）

- 用 C/C++/Cython 编写的模块
- 编译后性能高
- 示例：`_ta_lib.pyd`, `_ssl.pyd`

#### 3. 包（Package）

- 包含 `__init__.py` 的目录
- 可以包含子模块和子包
- 示例：`vnpy/`, `numpy/`

#### 4. 命名空间包（Namespace Package）

- 不包含 `__init__.py` 的目录
- 跨多个位置的包分发
- 示例：`jaraco`（位于 `setuptools/_vendor/jaraco`）

### 三、PyInstaller 打包机制

#### 1. 单文件模式（--onefile）

```
MeowTrader.exe          # 单一可执行文件
└── (运行时解压到临时目录)
    └── _internal/      # 解压后的内容
```

**特点**：
- 只有一个 `.exe` 文件
- 启动时会解压到临时目录（`%TEMP%/_MEIxxxxx`）
- 启动较慢（需要解压）
- 便于分发（单个文件）

#### 2. 目录模式（--onedir，默认）

```
MeowTrader/
├── MeowTrader.exe      # 启动器
└── _internal/          # 所有依赖
    ├── *.pyd
    ├── *.dll
    ├── vendor/
    └── ...
```

**特点**：
- 多个文件/目录
- 启动较快（无需解压）
- 便于调试（可以直接访问文件）

#### 3. 模块收集机制

PyInstaller 通过以下方式收集模块：

- **静态分析**：分析 `import` 语句
- **隐式导入**：通过 `--hidden-import` 指定
- **钩子脚本**：通过 `hooks/` 目录自定义收集逻辑
- **数据文件**：通过 `--add-data` 指定

## 七、目录结构特点

### 1. 扁平化结构

PyInstaller 将所有 Python 包扁平化放在 `_internal/` 目录中，而不是嵌套结构。

### 2. 路径处理

- **开发环境**：`from vnpy.trader import ...` 从 `vendor/vnpy/` 导入
- **打包环境**：同样从 `_internal/vendor/vnpy/` 导入
- 通过 `bootstrap.py` 的 `setup_vendor_path()` 确保路径正确

### 3. DLL 位置

- Python 扩展模块（`.pyd`）：直接在 `_internal/` 根目录
- Gateway API DLL：在各自的 `vnpy_xxx/api/` 目录中
- 系统 DLL：在 `_internal/` 根目录

### 4. 资源文件

- 配置文件：`config/` 目录
- 图标文件：保留在各自模块的 `ui/` 目录
- 数据文件：如 `setuptools/_vendor/` 通过 `--add-data` 添加

## 八、常见问题

### Q1: 为什么没有单独的 `jaraco/` 目录？

**A**: `jaraco` 不是独立安装的包，而是位于 `setuptools/_vendor/jaraco`。PyInstaller 无法通过命名空间包机制自动收集，需要通过 `--add-data` 将 `setuptools/_vendor` 目录添加进去。

### Q2: `vendor/` 目录为什么存在？

**A**: `vendor/` 目录包含项目自维护的模块（不在 PyPI 中），通过 `--add-data vendor;vendor` 完整复制。这些模块需要保持原有结构，便于运行时导入。

### Q3: 为什么有这么多 DLL 文件？

**A**: 
- Windows API DLL：用于兼容性
- Visual C++ 运行时：编译的扩展模块需要
- OpenSSL DLL：HTTPS/加密需要
- Gateway DLL：各个交易所接口需要

### Q4: `base_library.zip` 是什么？

**A**: Python 标准库（纯 Python 模块）的压缩包，PyInstaller 压缩后减小体积。运行时自动解压到内存。

## 九、优化建议

### 1. 减小体积

- 使用 `--exclude-module` 排除不需要的模块
- 使用 `--strip` 去除调试信息（需要 strip 工具）
- 考虑使用 `--onedir` 而不是 `--onefile`（减少解压时间）

### 2. 提高启动速度

- `--onedir` 模式比 `--onefile` 启动更快（无需解压）
- 减少不必要的模块收集

### 3. 路径处理

- 确保 `vendor/` 路径正确添加到 `sys.path`
- 使用相对路径而不是绝对路径
