## 核心框架模块

### 1. vnpy（核心框架）

**包名**: `vnpy`  
**版本**: 4.3.0  
**位置**: `src/vnpy-4.3.0/vnpy/`

**功能**: VeighNa 的核心框架，提供基础架构和通用功能。

#### 主要子模块：

##### 1.1 vnpy.event（事件引擎）
- **位置**: `vnpy/event/engine.py`
- **功能**: 事件驱动架构的核心
- **详细作用**: 
  - **发布-订阅模式**: 模块可以订阅感兴趣的事件，当事件发生时自动通知
  - **模块解耦**: 模块间不直接调用，通过事件通信，降低耦合度
  - **异步处理**: 支持异步事件处理，提高系统响应速度
  - **事件路由**: 自动将事件路由到所有订阅者
- **关键类**: 
  - `EventEngine`: 事件引擎，管理所有事件的发布和订阅
  - `Event`: 事件对象，包含事件类型和数据
  - `HandlerType`: 处理器类型（同步/异步）
- **事件类型**: 
  - `EVENT_TICK`: Tick 行情事件
  - `EVENT_BAR`: K 线事件
  - `EVENT_ORDER`: 委托事件
  - `EVENT_TRADE`: 成交事件
  - `EVENT_POSITION`: 持仓事件
  - `EVENT_ACCOUNT`: 账户事件
- **学习要点**:
```python
# 事件类型定义
EVENT_TICK = "eTick"      # Tick行情事件
EVENT_ORDER = "eOrder"    # 委托事件
EVENT_TRADE = "eTrade"    # 成交事件

# 事件引擎工作流程
from vnpy.event import EventEngine, Event

event_engine = EventEngine()

# 注册事件处理函数
def on_tick(event: Event):
    tick = event.data
    print(f"收到Tick: {tick.last_price}")

event_engine.register(EVENT_TICK, on_tick)  # 注册事件处理

# 发布事件
tick_data = TickData(...)
event_engine.put(Event(EVENT_TICK, tick_data))  # 发布事件
```
- **关键文档**:
  - 阅读源码: `vnpy/event/engine.py`
  - 理解: Event、EventEngine、HandlerType
- **使用场景**: 所有模块的基础，无需直接使用，但需要理解其工作原理
- **重要性**: 理解事件驱动架构是理解 VeighNa 系统的关键

##### 1.2 vnpy.trader（交易核心）
- **位置**: `vnpy/trader/`
- **功能**: 交易系统的核心引擎
- **主要组件**:
  - `engine.py`: 
    - `MainEngine` - 主引擎，统一管理所有 Gateway 和 App
    - `BaseEngine` - 基础引擎，提供通用功能
  - `gateway.py`: 
    - `BaseGateway` - 交易接口基类，所有 Gateway 必须继承
    - 定义了 Gateway 的标准接口（connect, subscribe, send_order 等）
  - `app.py`: 
    - `BaseApp` - 应用模块基类，所有 App 必须继承
    - `BaseEngine` - 应用引擎基类
  - `object.py`: 
    - 数据对象定义（TickData, BarData, OrderData, TradeData, PositionData, AccountData 等）
    - 所有模块使用统一的数据格式
  - `constant.py`: 
    - 常量定义（交易所、订单类型、方向、状态等）
    - 提供枚举类型和常量值
  - `database.py`: 
    - 数据库接口抽象，定义数据库的标准接口
    - 支持多种数据库实现（SQLite、PostgreSQL、MySQL 等）
  - `ui/`: 
    - 图形界面组件
    - `FluentMainWindow` - Fluent Design 风格主窗口
    - `Widget` - UI 组件基类
- **学习要点**:
```python
from vnpy.event import EventEngine
from vnpy.trader.engine import MainEngine

# 创建事件引擎和主引擎
event_engine = EventEngine()
main_engine = MainEngine(event_engine)

# 添加交易接口（Gateway）
main_engine.add_gateway(CtpGateway)      # 添加交易接口

# 添加应用模块（App）
main_engine.add_app(CtaStrategyApp)      # 添加策略应用
```
- **关键文档**:
  - 阅读源码: `vnpy/trader/engine.py`
  - 示例: `examples/veighna_trader/run.py`

##### 1.2.1 数据对象 (Data Objects)
- **位置**: `vnpy/trader/object.py`
- **概念**: 标准化的数据结构，所有模块使用统一的数据格式
- **必须掌握的数据对象**:
  - `TickData`: Tick行情数据（最新价、买一卖一、成交量等）
  - `BarData`: K线数据（开高低收、成交量、持仓量等）
  - `OrderData`: 委托数据（订单号、价格、数量、状态等）
  - `TradeData`: 成交数据（成交价、成交量、时间等）
  - `PositionData`: 持仓数据（持仓量、持仓成本、盈亏等）
  - `AccountData`: 账户数据（余额、可用资金、冻结资金等）
  - `ContractData`: 合约数据（合约代码、交易所、合约属性等）
- **关键文档**:
  - 阅读源码: `vnpy/trader/object.py`
  - 常量定义: `vnpy/trader/constant.py`
- **学习要点**:
  - 理解每个数据对象的字段含义
  - 理解常量定义（Direction、Offset、Status等）
  - 理解数据对象在模块间的传递方式

- **详细功能**:

  - **图表管理**: 管理多个图表窗口和图层

  - 行情展示（实时 K 线图）
  - 技术分析（叠加技术指标）

##### 1.4 vnpy.rpc（RPC 通信）
- **位置**: `vnpy/rpc/`
- **功能**: 远程过程调用，支持分布式部署
- **详细功能**:
  - **RPC 服务器**: 提供远程调用服务，暴露本地功能
  - **RPC 客户端**: 连接到远程服务器，调用远程功能
  - **数据序列化**: 自动序列化和反序列化数据
  - **连接管理**: 管理 RPC 连接的生命周期
- **组件**:
  - `server.py`: RPC 服务器实现
  - `client.py`: RPC 客户端实现
  - `common.py`: 通用功能和工具
- **用途**: 
  - 多机部署（策略服务器和交易服务器分离）
  - 远程访问（通过网络访问远程交易系统）
  - 系统集成（集成到其他系统）
- **特点**: 基于 ZeroMQ 实现，高性能、低延迟

##### 1.5 vnpy.alpha（Alpha 研究）
- **位置**: `vnpy/alpha/`
- **功能**: 因子研究和机器学习策略开发

  - **机器学习**: 提供机器学习模型（Lasso、LightGBM、MLP 等）
  - **策略回测**: 支持 Alpha 策略的回测

- **用途**:

  - Alpha 策略研究和回测
- **特点**: 受 Qlib 启发，提供完整的 Alpha 研究工具链

## 交易接口模块（Gateway）

Gateway 是连接不同交易系统的接口模块，每个交易所/交易系统都有对应的 Gateway。

### Gateway 基础概念

#### 什么是 Gateway？
- **概念**: 对接不同交易系统的接口
- **位置**: `vnpy/trader/gateway.py` (基类)
- **作用**: 将不同交易所的 API 封装成统一的标准接口

#### Gateway 基类 (BaseGateway)
- **必须实现的方法**:
  - `connect()`: 连接交易所
  - `subscribe()`: 订阅行情
  - `send_order()`: 发送订单
  - `cancel_order()`: 撤销订单
  - `query_account()`: 查询账户
  - `query_position()`: 查询持仓
- **回调函数**:
  - `on_tick()`: Tick行情回调
  - `on_order()`: 委托回报回调
  - `on_trade()`: 成交回报回调
  - `on_account()`: 账户更新回调
  - `on_position()`: 持仓更新回调

#### 学习要点
```python
from vnpy.trader.gateway import BaseGateway

class MyGateway(BaseGateway):
    def connect(self, setting: dict):
        # 连接交易所
        pass
    
    def subscribe(self, req: SubscribeRequest):
        # 订阅行情
        pass
    
    def send_order(self, req: OrderRequest):
        # 发送订单
        pass
```

#### 关键文档
- `docs/community/info/gateway.md` - Gateway接口说明
- 示例Gateway: `vnpy_ctp` (需要单独安装)

### 策略相关模块

#### vnpy_ctastrategy ⭐（本项目使用）

**模块名称**: CTA自动交易模块  
**版本**: 1.3.0  
**位置**: `src/vnpy_ctastrategy-1.3.0/`

**详细功能**:

1. **策略生命周期管理**
   - 策略实例创建：基于策略类创建多个策略实例，每个实例可交易不同合约
   - 策略初始化：自动加载历史数据并回放，完成策略初始化
   - 策略启动：策略初始化完成后可启动，开始接收实时行情并发出交易信号
   - 策略停止：随时停止策略运行，保存当前状态
   - 策略移除：删除策略实例及其配置

2. **策略参数管理**
   - 参数编辑：支持在运行时修改策略参数（如开仓比例、止盈止损等）
   - 参数保存：策略参数自动保存到配置文件
   - 参数验证：确保参数类型和范围正确

3. **策略状态监控**
   - 实时监控策略运行状态（初始化状态、交易状态）
   - 显示策略内部变量（持仓、盈亏、信号等）
   - 策略日志输出和查看

4. **多实例管理**
   - 同一策略类可创建多个实例
   - 每个实例可交易不同合约
   - 每个实例可有不同的参数配置

**核心特性**:
- 支持单合约、单方向的 CTA 策略
- 自动处理历史数据回放
- 支持策略参数的动态调整
- 提供图形界面进行策略管理
- 策略状态持久化保存

## VNStation 和 VNTrader 说明

本文介绍 VeighNa 生态里常见的两个概念（或目录）：**VNStation（VeighNa Station）** 和 **VNTrader（.vntrader 工作目录）**，以及它们和你当前项目的关系、推荐用法。

### 1. VNStation 是什么？

- **VNStation（VeighNa Station）** 是 VeighNa 提供的**图形化桌面程序**：
  - 提供统一的界面来管理：行情、交易接口、CTA 策略、组合策略、风控、数据管理、Web 终端等。
  - 本质上是一个基于 `vnpy` 的 GUI 程序，内部加载了各种应用（App）。
- 启动方式：
  - 官方通常通过桌面快捷方式或命令行运行 `python -m veighna_station`。
  - 你当前项目中有一个 `station_launcher_correct.py`：
    - 作用：**在同一个 Python 进程中运行 Station，并在启动前打补丁注入新的网关（OKX、Binance 等）**。
    - 好处：你可以在本项目环境中直接启动 Station，同时使用本项目的源码（比如你的 DynamicGrid 策略）。

简单理解：**VNStation = 图形界面总控台**，用来操作和管理一切。

### 2. VNTrader / `.vntrader` 是什么？

- **`.vntrader` 是 vn.py/VeighNa 的"工作目录"**，通常用来存放：
  - **数据库文件**（默认 SQLite）：`database.db`
  - **全局配置**：`vt_setting.json`
  - **各应用配置**：
    - `cta_backtester_setting.json`：CTA 回测模块的上次参数（策略名、合约、时间区间等）
    - `connect_xxx.json`：各交易所接口的连接配置（API Key、Server 等）
    - `data_recorder_setting.json`：行情录制配置
    - `paper_account_setting.json` / `paper_account_data.json`：模拟账户配置/数据
    - `portfolio_manager_setting.json` 等组合策略相关配置
    - `web_trader_setting.json` 等 Web 端配置
  - **日志目录**：`log/vt_xxx.log`
- 命名方式：
  - 默认工作目录名就是 `.vntrader`（带点），常见位置：
    - `C:\Users\<用户名>\.vntrader`
    - 或者当前工作目录下的 `.vntrader`（取决于你从哪个路径启动 Station/脚本）。

### 6. 常见问题（FAQ）

#### Q1：为什么我电脑上有多个 `.vntrader` 目录？

- 可能原因：
  - 你曾在不同路径下启动过 vntrader/Station；
  - 某些脚本在不同工作目录下运行，自动在各自目录生成 `.vntrader`。
- 解决思路：
  - 选择一个你认定的"主工作区"（比如当前项目），以后尽量**都在这个目录下启动 Station 和脚本**。
  - 其它旧的 `.vntrader` 可以先备份，再视情况清理。

#### Q2：我怎么确认当前使用的是哪个 `.vntrader`？

- 看程序的**当前工作目录（CWD）**：
  - 在终端中：`cd` 显示的路径；
  - 在脚本里：`import os; print(os.getcwd())`。
- 一般规则：
  - 如果当前目录下存在 `.vntrader`，就会优先使用这里；
  - 不存在时，则使用默认位置（例如 `C:\Users\<用户名>\.vntrader`）。

#### Q3：DynamicGrid 回测时，数据从哪里来？

- 如果你使用的是 `BacktestingEngine.load_data()` 且数据库配置为 SQLite：
  - 数据来自当前工作目录的 `.vntrader/database.db`。
- 因此：
  - 在 Station 的 Datamanager 中下载的 BTCUSDT\_SPOT\_OKX 数据，会保存在这个 `database.db`；
  - 你的脚本只要在同一目录下运行，就能直接用到这些 K 线。
