# PyInstaller 打包机制说明

## 目录结构说明

### `vendor/` - 真正的源码（第三方模块）

`vendor/` 目录包含的是**本软件真正的源码**：
- `vendor/vnpy/`：vnpy 核心框架
- `vendor/gateways/`：交易接口（vnpy_okx, vnpy_binance 等）
- `vendor/apps/`：功能模块（vnpy_ctastrategy, vnpy_datamanager 等）

**打包处理**：通过 `--add-data` **原样复制**到打包结果中

**问题**：`.py` 源代码文件会暴露，可以查看源码

### `core/` - 产品层封装

`core/` 目录是**产品层封装代码**，用于：
- `ProductEngine`：封装 vnpy MainEngine，提供统一 API
- `ConfigManager`：配置管理和加载
- `RuntimeManager`：运行时环境管理
- `ModuleRegistry`：模块注册和管理

**打包处理**：PyInstaller 通过分析 `app/desktop/main.py` 的导入（`from meowtrader.core import ...`）自动收集，打包到 `base_library.zip`（已编译为 `.pyc`）

### `app/` - 启动入口

`app/` 目录是**应用的启动入口**，包含：
- `app/desktop/`：桌面客户端入口（GUI 模式）
- `app/server/`：服务端入口（无 UI，运行策略）
- `app/web/`：Web 服务入口（WebTrader）

**打包处理**：入口脚本 `app/desktop/main.py` 被打包为 `MeowTrader.exe`，`app/` 的其他部分被自动收集到 `base_library.zip`

### 为什么之前没有 `core` 和 `app` 也能运行？

**原因**：
- `core` 和 `app` 模块被打包到了 `base_library.zip`（已编译为 `.pyc`）
- Python 可以从压缩包中加载 `.pyc` 文件
- 只是不在 `_internal/` 目录结构中可见，但功能正常

## 为什么 `vendor` 在 `_internal` 中，而 `core` 和 `app` 不在？

### 问题现象

打包后 `dist/MeowTrader/_internal/` 目录中：
- ✅ `vendor/` 目录存在
- ✅ `config/` 目录存在
- ❌ `core/` 目录不存在
- ❌ `app/` 目录不存在

### 原因分析

#### 1. `vendor` 和 `config` 为什么存在？

这两个目录通过 `--add-data` **显式添加**到了打包结果中：

```python
# packaging/pyinstaller/build.py
data_files = [
    (str(PROJECT_ROOT / "config"), "config"),      # ✅ 显式添加
    (str(PROJECT_ROOT / "vendor"), "vendor"),      # ✅ 显式添加
]
```

`--add-data` 的作用：
- 将目录/文件**原样复制**到打包结果中
- 保持目录结构
- 用于非 Python 文件或需要保持目录结构的模块

#### 2. `core` 和 `app` 为什么不在？

这两个目录**没有通过 `--add-data` 添加**，PyInstaller 通过以下方式处理：

1. **分析导入语句**：
   - `app/desktop/main.py` 中：`from meowtrader.core import ...`
   - PyInstaller 会自动发现并收集 `meowtrader.core` 模块

2. **打包方式**：
   - 纯 Python 模块通常被打包到 `base_library.zip`（标准库压缩包）
   - 或者编译成 `.pyc` 文件，但不在目录结构中
   - 运行时从压缩包中动态加载

3. **为什么不显式添加？**
   - 历史原因：`vendor` 需要显式添加（因为不在标准 Python 路径中）
   - `core` 和 `app` 被误认为会自动处理（但实际上没有显式添加）

### 问题

虽然 `core` 和 `app` 模块被打包了（在 `base_library.zip` 中），但存在以下问题：

1. **目录结构不一致**：`vendor` 有目录，`core` 和 `app` 没有
2. **调试困难**：无法直接查看 `core` 和 `app` 的源代码文件
3. **可能丢失文件**：某些非 `.py` 文件可能没有被正确收集

### 解决方案

#### 方案 1：显式添加 `core` 和 `app`（推荐）

将 `core` 和 `app` 也通过 `--add-data` 添加，保持一致的目录结构：

```python
data_files = [
    (str(PROJECT_ROOT / "config"), "config"),
    (str(PROJECT_ROOT / "vendor"), "vendor"),
    (str(PROJECT_ROOT / "core"), "core"),      # ✅ 新增
    (str(PROJECT_ROOT / "app"), "app"),        # ✅ 新增
]
```

**优点**：
- 目录结构一致
- 便于调试（可以看到源代码文件）
- 确保所有文件都被包含

**缺点**：
- 打包体积略微增加（但影响很小）

#### 方案 2：只添加项目根目录到 `--paths`

只告诉 PyInstaller 在哪里查找模块，但不显式添加：

```python
"--paths", str(PROJECT_ROOT),  # ✅ 新增
```

**优点**：
- 打包体积小

**缺点**：
- 目录结构不一致
- 可能丢失某些文件

### 推荐做法

**同时使用两种方式**：

1. **添加项目根目录到 `--paths`**：
   - 确保 PyInstaller 能找到所有模块
   - 用于分析阶段的模块查找

2. **显式添加 `core` 和 `app` 到 `--add-data`**：
   - 确保目录结构一致
   - 确保所有文件都被包含

### 实施

已在 `packaging/pyinstaller/build.py` 中实施：

```python
# 添加项目根目录到搜索路径
"--paths", str(PROJECT_ROOT),

# 显式添加 core 和 app 目录
data_files = [
    (str(PROJECT_ROOT / "config"), "config"),
    (str(PROJECT_ROOT / "vendor"), "vendor"),
    (str(PROJECT_ROOT / "core"), "core"),      # ✅ 新增
    (str(PROJECT_ROOT / "app"), "app"),        # ✅ 新增
]
```

### 验证

重新打包后，检查 `_internal` 目录：

```bash
dist/MeowTrader/_internal/
├── vendor/        ✅ 存在
├── config/        ✅ 存在
├── core/          ✅ 应该存在（修复后）
└── app/           ✅ 应该存在（修复后）
```

## PyInstaller 打包机制总结

### `--paths` vs `--add-data`

| 参数 | 作用 | 结果 |
|------|------|------|
| `--paths` | 告诉 PyInstaller 在哪里**查找**模块（分析阶段） | 不会添加到打包结果 |
| `--add-data` | 将目录/文件**原样复制**到打包结果 | 会出现在 `_internal/` 目录中 |

### 模块收集方式

1. **自动分析**：
   - PyInstaller 分析入口脚本的 `import` 语句
   - 递归收集所有依赖模块
   - 纯 Python 模块打包到 `base_library.zip`

2. **显式指定**：
   - `--hidden-import`：指定隐式导入的模块
   - `--add-data`：指定需要保持目录结构的目录
   - `--add-binary`：指定二进制文件（.dll, .pyd）

### 目录处理策略

| 目录类型 | 推荐方式 | 原因 |
|---------|---------|------|
| **vendor/** | `--add-data` | 第三方模块，不在标准路径中 |
| **config/** | `--add-data` | 配置文件，需要保持目录结构 |
| **core/** | `--add-data` + `--paths` | 项目核心模块，需要保持结构 |
| **app/** | `--add-data` + `--paths` | 应用入口，需要保持结构 |
| **Python 标准库** | 自动处理 | PyInstaller 自动收集 |
