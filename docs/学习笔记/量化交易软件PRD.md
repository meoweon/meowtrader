# 量化交易软件 PRD（基于 vnpy 源码产品化）

## 1. 背景与目标

### 1.1 背景
- 当前以 vnpy 源码为基础进行二次开发，目标是形成可打包、可分发、可维护的商业化产品。
- 需支持不同版本形态（精简版/专业版/客户定制版）与多入口、多 UI、多平台部署。

### 1.2 产品目标
- 形成稳定的“产品层”架构，隔离 vnpy 内核变化。
- 实现模块化加载与裁剪，可按配置组合功能。
- 支持多入口（桌面 UI / Web UI / Server / 无 UI）。
- 支持 Windows 与 Linux 打包分发。

### 1.3 成功标准
- 版本切换无需改代码，仅调整配置。
- UI 可替换，不影响交易核心。
- 新模块接入不影响已有版本。
- 打包产物可独立运行并可升级。

---

## 2. 用户与场景

### 2.1 目标用户
- 个人量化交易者
- 小型量化团队
- 企业客户（定制部署）

### 2.2 主要场景
- 版本分级：精简版只含基础交易与策略运行；专业版包含回测、数据管理、风控；客户版按需求裁剪。
- 多入口：桌面端交易、服务器端策略运行、Web 端远程监控。
- 多平台：Windows 日常交易，Linux 服务器运行策略与 RPC 服务。

---

## 3. 需求范围

### 3.1 功能范围
- 核心交易引擎（基于 vnpy MainEngine）
- 事件引擎、订单管理、日志系统
- 网关（OKX、Binance 等）
- App 模块（CTA、回测、数据管理、风控等）
- 数据库模块（SQLite、PostgreSQL）
- WebTrader / RPC 服务

### 3.2 非功能范围
- 版本控制与许可（模块授权、功能开关）
- 配置驱动的模块加载
- 跨平台打包
- 统一日志、诊断与错误收集

---

## 4. 产品分层与架构

### 4.1 分层结构
- 入口层：多种启动方式（桌面 UI / Web UI / Server / CLI）
- 产品层：统一引擎封装、模块注册、功能开关、版本控制
- 内核层：vnpy 源码（MainEngine、EventEngine、Gateway、App）

### 4.2 产品层职责
- 统一创建与管理 MainEngine/EventEngine
- 按配置加载 Gateway/App/Database
- 版本分级与功能权限控制
- 提供稳定 API 给 UI 和服务层
- 统一退出与资源释放

---

## 5. 核心需求

### 5.1 模块化加载
- 必须支持配置化启用/禁用 Gateway、App、数据库模块。
- 允许按版本（精简/专业/定制）动态决定功能组合。

### 5.2 多入口支持
- 桌面端入口：提供完整 UI 与交易操作。
- 服务端入口：无 UI，仅运行策略、网关与服务。
- Web 入口：提供远程访问与监控。

### 5.3 多 UI 兼容
- 支持 Fluent UI 作为默认桌面方案。
- 预留 Web UI、轻量 UI 与无 UI 运行模式。
- UI 与核心引擎解耦。

### 5.4 版本与授权
- 不同版本加载不同模块。
- 支持功能开关与模块授权。
- 授权状态影响 UI 可见性与功能可用性。

### 5.5 配置与资源管理
- 配置中心化管理（默认配置、用户配置、版本配置）。
- 统一资源路径与数据目录策略。
- 兼容多平台路径差异。

---

## 6. 版本规划

### 6.1 精简版
- 基础交易、网关连接
- CTA 策略引擎
- 基础监控与日志

### 6.2 专业版
- 精简版全部功能
- 回测引擎、数据管理
- 风险管理、组合策略
- 可选 WebTrader 与 RPC

### 6.3 客户定制版
- 基于专业版裁剪
- 按需求定制功能模块与 UI

---

## 7. 关键流程

### 7.1 启动流程
1. 读取版本与授权配置
2. 初始化事件引擎与主引擎
3. 按配置加载 Gateway/App/Database
4. 选择入口模式（桌面/UI/服务端）
5. 启动 UI 或服务

### 7.2 退出流程
1. 停止策略与服务
2. 断开网关
3. 保存配置与状态
4. 释放资源并退出

---

## 8. 技术与实现要求

### 8.1 目录结构要求
- vnpy 源码保持独立目录，作为内核层引用。
- 产品层与 UI 层单独维护，避免直接修改内核。
- 统一注册与配置中心。

### 8.2 可维护性要求
- UI 与引擎解耦
- 模块加载配置化
- 可扩展可裁剪
- 可追踪日志与错误

---

## 9. 交付与分发

### 9.1 打包目标
- Windows 可执行安装包
- Linux 可执行包或容器镜像

### 9.2 运行模式
- Desktop：桌面 UI
- Server：无 UI 服务端
- Web：远程 Web 控制台

---

## 10. 风险与对策

### 10.1 风险
- vnpy 升级导致不兼容
- 模块依赖复杂、版本冲突
- 多入口与多 UI 增加维护成本

### 10.2 对策
- 通过产品层封装，隔离 vnpy 变化
- 版本配置化管理
- 统一模块注册与加载策略

---
