# 打包依赖说明

本文档说明 MeowTrader 项目中打包时可能遇到的依赖问题及其解决方案。

## setuptools

### setuptools 是什么？

`setuptools` 是 Python 生态中最基础的**打包与分发库**，提供以下核心功能：

1. **构建系统（Build System）**
   - 将 Python 代码打包成可分发的格式（sdist、wheel）
   - 支持 `setup.py`、`setup.cfg`、`pyproject.toml` 等多种配置方式
   - 作为构建后端（build-backend）在 `pyproject.toml` 中使用（PEP 517/621）

2. **依赖管理（Dependency Management）**
   - 定义项目的依赖关系（`install_requires`, `extras_require`）
   - 解析和安装依赖包
   - 管理可选依赖组（optional-dependencies）

3. **扩展模块编译**
   - 编译 C/C++ 扩展模块（`.pyd`, `.so`）
   - 处理编译依赖和链接库

4. **Entry Points 机制**
   - 定义命令行工具入口点
   - 实现插件发现和加载机制

5. **包资源访问**
   - 提供 `pkg_resources` 模块访问包内资源文件
   - 查询已安装包的元数据（版本、依赖等）

### setuptools 的组成

```
setuptools/
├── __init__.py          # 主模块
├── _vendor/             # 内嵌的第三方依赖（vendor）
│   ├── jaraco/          # jaraco 工具库集合
│   │   ├── text/        # 文本处理
│   │   ├── functools/   # 函数式工具
│   │   └── context/     # 上下文管理
│   ├── packaging/       # 包管理工具
│   └── ...
├── distutils/           # distutils 扩展
└── ...
```

**关键点**：
- `setuptools._vendor.*` 是**内嵌依赖**（vendored dependencies），这些库的代码直接包含在 setuptools 中
- 这些 vendor 包**不是独立安装的**，而是 setuptools 的一部分
- PyInstaller 打包时需要特别处理这些 vendor 依赖

### setuptools 版本与 pkg_resources

| setuptools 版本 | pkg_resources 状态 | 说明 |
|----------------|-------------------|------|
| < 81.0.0 | ✅ 正常使用 | `pkg_resources` 完全可用 |
| ≥ 81.0.0 | ⚠️ 已弃用 | `pkg_resources` 被标记为 deprecated |
| 未来版本 | ❌ 将被移除 | 计划在 2025-11-30 左右移除 |

**当前项目**：使用 `setuptools==80.9.0`（`pkg_resources` 仍可用）

### 为什么需要 setuptools？

在 MeowTrader 项目中，setuptools 主要用于：

1. **构建后端**：`pyproject.toml` 中指定 `build-system.requires = ["hatchling"]`（现代项目通常用 `hatchling` 或 `setuptools`）
2. **依赖管理**：通过 `pyproject.toml` 定义项目依赖
3. **提供 pkg_resources**：某些第三方库（如 PyInstaller）需要使用 `pkg_resources`

### 打包时的问题

PyInstaller 打包时，`setuptools` 的相关问题：

1. **不会自动包含 `pkg_resources`**
   - PyInstaller 可能不会自动检测到对 `pkg_resources` 的隐式依赖
   - 需要显式添加 `--hidden-import pkg_resources`

2. **vendor 依赖不会被自动收集**
   - `setuptools._vendor.jaraco` 等 vendor 包需要特殊处理
   - 使用 `--collect-submodules setuptools._vendor.jaraco` 收集

3. **避免收集整个 setuptools**
   - `--collect-all setuptools` 会收集大量不需要的内部模块
   - 推荐只收集必要的部分（`pkg_resources`、`setuptools._vendor.jaraco`）

## pkg_resources 和 jaraco

### pkg_resources 是什么？

`pkg_resources` 是 `setuptools` 库的一部分，提供以下功能：

- **访问包内资源文件**：读取配置文件、数据文件等（如 `resource_filename()`, `resource_string()`）
- **运行时发现插件**：通过 entry point 机制发现和加载插件
- **管理依赖元数据**：查询包版本、依赖关系等
- **动态导入和版本检查**：运行时检查和加载包

**注意**：`pkg_resources` 已被标记为弃用（deprecated），计划在 **2025年11月30日** 左右移除。推荐使用 Python 标准库的 `importlib.resources` 或 `importlib.metadata` 作为替代。

### jaraco 是什么？

`jaraco` 是一个 Python 工具库集合，由 jaraco 组织维护，包含多个实用模块：

- **`jaraco.text`**：文本处理工具（如 `drop_comment`, `join_continuation`, `yield_lines`）
- **`jaraco.functools`**：函数式编程工具
- **`jaraco.context`**：上下文管理工具

**重要**：在新版本的 `setuptools` 中，`jaraco` 不是独立安装的包，而是位于 `setuptools._vendor.jaraco`。`pkg_resources` 通过命名空间包机制导入 `jaraco.text` 等模块。

### 为什么打包时会出现 "No module named 'jaraco'" 错误？

PyInstaller 在打包时可能无法正确识别：
1. `jaraco` 的实际位置（`setuptools._vendor.jaraco`）
2. `pkg_resources` 对 `jaraco` 的依赖关系
3. 命名空间包的导入机制

### 解决方案

在 `packaging/pyinstaller/build.py` 中：

1. **添加 hidden imports**：
   ```python
   "jaraco",
   "jaraco.text",
   "jaraco.functools",
   "jaraco.context",
   "setuptools._vendor.jaraco",
   "setuptools._vendor.jaraco.text",
   # ...
   ```

2. **使用 PyInstaller 收集选项**：
   ```python
   args.extend(["--collect-all", "pkg_resources"])
   args.extend(["--collect-submodules", "setuptools._vendor.jaraco"])
   args.extend(["--collect-submodules", "jaraco"])
   ```

## 其他常见依赖

### more_itertools

`more_itertools` 是 `itertools` 的扩展，提供额外的迭代器工具。某些包（如 `jaraco`）可能依赖它。

**处理方式**：已在 hidden_imports 中添加，PyInstaller 会自动收集（如果已安装）。

### packaging

`packaging` 用于处理版本号、依赖解析等。通常由 `setuptools` 自动安装，位于 `setuptools._vendor.packaging`。

**处理方式**：如果需要，可以通过 `--collect-all setuptools` 收集（但会包含大量不需要的模块），或只收集特定部分：

```python
"setuptools._vendor.packaging",
"setuptools._vendor.packaging.version",
"setuptools._vendor.packaging.specifiers",
```

## 依赖关系图

```
setuptools (80.9.0)
├── pkg_resources (运行时模块)
│   ├── jaraco.text (位于 setuptools._vendor.jaraco.text)
│   ├── jaraco.functools (位于 setuptools._vendor.jaraco.functools)
│   ├── jaraco.context (位于 setuptools._vendor.jaraco.context)
│   └── more_itertools (独立包，可能被依赖)
├── setuptools._vendor.jaraco (内嵌依赖)
│   ├── text/
│   ├── functools/
│   └── context/
└── setuptools._vendor.packaging (内嵌依赖)
    ├── version/
    └── specifiers/
```

**关键点**：
- `pkg_resources` 依赖 `jaraco.*`，但 `jaraco` 不在 `pkg_resources` 目录中
- `jaraco` 实际位于 `setuptools._vendor.jaraco`
- PyInstaller 需要同时收集这两个位置的模块

## 依赖收集策略

### 推荐的收集顺序

1. **显式添加常用 hidden imports**（如 `pkg_resources`, `jaraco.*`）
   - 包括 `setuptools._vendor.*` 路径的模块
   
2. **使用 `--collect-all` 收集完整的包**（如 `pkg_resources`）
   - 确保收集所有子模块和数据文件
   
3. **使用 `--collect-submodules` 收集子模块**（如 `jaraco`, `setuptools._vendor.jaraco`）
   - 递归收集所有子模块

### MeowTrader 项目的配置

在 `packaging/pyinstaller/build.py` 中的当前配置：

```python
# Hidden imports
hidden_imports = [
    "pkg_resources",
    "jaraco",
    "jaraco.text",
    "jaraco.functools",
    "jaraco.context",
    "setuptools._vendor.jaraco",
    "setuptools._vendor.jaraco.text",
    "setuptools._vendor.jaraco.functools",
    "setuptools._vendor.jaraco.context",
    "more_itertools",
]

# PyInstaller 收集选项
args.extend(["--collect-all", "pkg_resources"])
args.extend(["--collect-submodules", "setuptools._vendor.jaraco"])
args.extend(["--collect-submodules", "jaraco"])
```

### 避免过度收集

- ❌ **不要**使用 `--collect-all setuptools`（会收集大量不需要的内部模块，如 `setuptools.command.*`、`setuptools.dist.*` 等）
- ✅ **只收集**实际需要的模块和子模块
- ✅ **同时收集**命名空间包路径（`jaraco`）和实际路径（`setuptools._vendor.jaraco`）

## 检查缺失依赖的方法

### 1. 检查 setuptools 安装

```bash
# 检查 setuptools 版本和位置
python -c "import setuptools; print(f'setuptools {setuptools.__version__} at {setuptools.__file__}')"

# 或使用 pip
pip show setuptools
```

### 2. 运行时测试

运行打包后的应用程序，观察是否有 `ModuleNotFoundError`。常见错误：

- `ModuleNotFoundError: No module named 'jaraco'` → 缺少 jaraco 收集
- `ModuleNotFoundError: No module named 'pkg_resources'` → 缺少 pkg_resources 收集
- `ModuleNotFoundError: No module named 'setuptools._vendor.jaraco'` → 缺少 vendor 依赖收集

### 3. 开发环境验证

在开发环境中测试所有相关导入：

```python
# 测试 setuptools 基本功能
import setuptools
print(f"setuptools version: {setuptools.__version__}")

# 测试 pkg_resources
import pkg_resources
dist = pkg_resources.get_distribution('setuptools')
print(f"Found setuptools {dist.version}")

# 测试 jaraco（命名空间包路径）
from jaraco.text import drop_comment
print("jaraco.text imported via namespace")

# 测试 jaraco（实际路径）
from setuptools._vendor.jaraco.text import drop_comment
print("jaraco.text imported via setuptools._vendor")

# 如果这些导入都成功，说明依赖可用
```

### 4. 检查打包日志

查看 PyInstaller 的警告和错误信息：

```bash
# 查找隐藏导入错误
grep -i "hidden import.*not found" build.log

# 查找 jaraco/pkg_resources 相关警告
grep -i "jaraco\|pkg_resources" build.log
```

### 5. 使用 `pyi_rth_pkgres.py`

PyInstaller 会生成 `pyi_rth_pkgres.py` 来处理 `pkg_resources`。如果这个文件运行时出错：

- 错误：`ModuleNotFoundError: No module named 'jaraco'`
  - **原因**：缺少 jaraco 收集
  - **解决**：添加 `--collect-submodules setuptools._vendor.jaraco`

- 错误：`ModuleNotFoundError: No module named 'pkg_resources'`
  - **原因**：pkg_resources 未被收集
  - **解决**：添加 `--hidden-import pkg_resources` 或 `--collect-all pkg_resources`

## 常见问题排查

### Q1: 为什么开发环境正常，但打包后报错？

**原因**：
- 开发环境中，Python 可以直接访问 `site-packages` 中的所有模块
- PyInstaller 打包时，只包含**显式导入**的模块
- `setuptools._vendor.*` 等 vendor 依赖是**隐式依赖**，需要手动收集

**解决**：
- 添加 hidden imports
- 使用 `--collect-submodules` 收集 vendor 依赖

### Q2: 是否应该使用 `--collect-all setuptools`？

**不推荐**：
- `--collect-all setuptools` 会收集大量不需要的模块（如 `setuptools.command.*`、`setuptools.dist.*` 等）
- 增加打包体积，可能引入不必要的依赖

**推荐**：
- 只收集需要的部分：`pkg_resources`、`setuptools._vendor.jaraco`
- 使用 `--collect-all pkg_resources` 而不是 `--collect-all setuptools`

### Q3: setuptools 版本应该固定吗？

**建议**：
- 当前项目使用 `setuptools==80.9.0`（`pkg_resources` 仍可用）
- 如果升级到 `setuptools>=81`，需要：
  1. 迁移所有 `pkg_resources` 使用到 `importlib.*`
  2. 或临时限制 `setuptools<81`（不推荐长期使用）

## 未来迁移建议

### 1. 逐步替换 `pkg_resources`

| 旧 API (`pkg_resources`) | 新 API (`importlib`) | 说明 |
|-------------------------|---------------------|------|
| `pkg_resources.resource_filename()` | `importlib.resources.files()` | 访问包资源文件 |
| `pkg_resources.get_distribution()` | `importlib.metadata.distribution()` | 获取包元数据 |
| `pkg_resources.iter_entry_points()` | `importlib.metadata.entry_points()` | 遍历 entry points |

**迁移示例**：

```python
# 旧方式 (pkg_resources)
import pkg_resources
config_file = pkg_resources.resource_filename('my_package', 'config.json')
version = pkg_resources.get_distribution('my_package').version

# 新方式 (importlib)
from importlib.resources import files
from importlib.metadata import distribution

config_file = files('my_package') / 'config.json'
version = distribution('my_package').version
```

### 2. 检查第三方库

- 如果项目依赖的库仍在使用 `pkg_resources`，考虑：
  1. 升级到支持新 API 的版本
  2. 提交 issue/PR 帮助库迁移
  3. 或暂时继续使用 `pkg_resources`（直到库更新）

### 3. 版本约束（临时方案）

如果暂时无法迁移，可以在 `pyproject.toml` 中限制：

```toml
[project]
requires-python = ">=3.13"
dependencies = [
    # ...
    "setuptools<81",  # 临时方案，不推荐长期使用
]
```

**注意**：这不是长期解决方案，应尽快迁移到 `importlib.*`。

## 总结

| 模块 | 位置 | 打包处理 | 状态 |
|------|------|---------|------|
| `setuptools` | `site-packages/setuptools/` | 构建时依赖，运行时不需要全部 | ✅ 正常 |
| `pkg_resources` | `site-packages/pkg_resources/` | 需要 `--collect-all` | ✅ 已配置 |
| `jaraco.*` | `setuptools._vendor.jaraco.*` | 需要 `--collect-submodules` | ✅ 已配置 |
| `more_itertools` | `site-packages/more_itertools/` | 自动收集（如已安装） | ✅ 已配置 |

**关键要点**：
1. `setuptools` 是构建和打包的基础工具
2. `pkg_resources` 依赖 `jaraco`，但 `jaraco` 位于 `setuptools._vendor.jaraco`
3. PyInstaller 需要同时收集命名空间包路径和实际路径
4. 未来应迁移到 `importlib.*` 替代 `pkg_resources`
